# v1: join the pieces

## Goal

A resident texts a problem. It becomes a row in the database, a card on the council dashboard, and a reply carrying a link. No manual step.

## Where it stands

- Channel works: real iMessages send and arrive, guards handle self, stale and duplicates.
- Data layer works: four tools, 65 passing tests, 68 synthetic reports seeded.
- Site works: `/council` behind a password and `/r/<token>`, served on the same port.
- **The gap:** the webhook never calls `save_report`. A test message left the count at 68 before and 68 after. That single missing call is v1.

## The change

Today: photo → `llm.chat` → reply text.

Tomorrow: photo → **triage** → **save_report** → reply with link.

### 1. `code/triage.py` (new, about 80 lines)

One DeepSeek call, JSON out, nothing else:

```json
{"is_report": true, "category_id": "pothole", "location": "Weston Lane",
 "description": "Pothole outside the school", "severity": "high", "confidence": 0.82}
```

- `category_id` must be in `tools.category_ids()`, otherwise `is_report: false`.
- We validate, not the model: unknown id rejected, confidence clamped, location required.
- Bad JSON: one retry with the parse error quoted back, then a plain question to the resident.

### 2. Wire it into `code/blue_bubbles.py`

The non-agent branch (lines 126 to 129) becomes:

1. `triage(text or photo)`
2. Not a report, reply with guidance, save nothing
3. `tools.save_report(category_id, location, description, severity, has_photo, reporter=sender)`
4. Duplicate, say it is already open and link the original
5. Otherwise reply with `SITE_URL/r/<link_token>`

`MODE=triage` is the new default. `MODE=echo` stays as a plain-chat fallback.

### 3. Config and vision

- `COUNCIL_PASSWORD` into `code/.env`, since `/council` is a 503 without it.
- `code/llm.py`: DeepSeek first for images with `reasoning: {"effort": "low"}`. DeepSeek returns empty content for images without that key, which we proved twice. Three lines, and OpenRouter's exhausted quota stops mattering.
